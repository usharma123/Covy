## Useful Capabilities

- Long-lived Rust file finder with one repository scan reused across repeated searches.
- Content grep modes for plain text, regex, and fuzzy matching.
- Typo-resistant fuzzy path and content matching.
- Frecency and query-history ranking backed by local storage.
- Git-aware result annotations for modified, staged, untracked, and ignored files.
- Background watcher and warm in-memory file/cache model.
- MCP server exposing agent-facing search tools.

## Packet28 Fit

`fff` is a strong candidate for replacing or augmenting parts of Packet28's custom `p28` search engine, especially fuzzy matching, frecency, git-aware ranking, and warm repeated-search performance.

It is not a blind drop-in replacement for current Packet28 search because Packet28 also owns:

- reducer packet shape and compact preview semantics
- raw artifact recovery and fetch handles
- fallback reasons and route/provenance reporting
- daemon index status and setup/doctor evidence
- real-repo parity artifacts under `docs/experiments/`
- local-first storage expectations under Packet28 paths and schemas
- the current Rust 1.75 / edition 2021 build contract; current `fff` sources use edition 2024, and crates.io currently advertises a nightly-tagged `fff-search` package, so direct linking needs an MSRV/build-policy decision

## Recommended Adapter Plan

1. Add an experimental backend enum such as `p28 --backend packet28-index|fff` only after the dependency/MSRV story is explicit.
2. Build a thin adapter that converts `fff` results into Packet28 `SearchResult` packets without changing public `p28` output, or launch `fff-mcp` as an optional peer if direct linking would break the release build.
3. Preserve current fallback fields, token estimates, path filtering, raw recovery handles, and compact output.
4. Run the real-repo suite with both backends and compare indexed hit rate, elapsed time, output token count, fallback count, memory use, and correctness against native `rg`.
5. Adopt `fff` only if the adapter improves repeated-search behavior without weakening Packet28's artifact and parity contracts.

## Current Decision

Do not replace Packet28 search immediately. Keep the fixed Packet28 indexed path as the default, and evaluate `fff` with an adapter plus the same real-repo evidence gate.
