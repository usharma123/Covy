# Packet28 Runtime Integration Smoke

This is a local runtime-integration evidence run for the RTK parity goal. It is not a full maturity claim by itself.

- Run id: RUNTIME_LIVE_20260512
- Workspace binary tested: `target/debug/Packet28`
- Installed runtimes observed:
  - Claude Code `2.1.139`
  - Gemini CLI `0.30.0`
  - OpenCode `1.14.48`
- Runtimes not available as executable commands in this environment: Cursor, Hermes

## Claude Code

Result: pass for real Claude Code hook invocation.

Setup used a temporary git repository and `Packet28 setup --runtime claude --root <temp-root> --yes`.

The real `claude --print --verbose --output-format stream-json --include-hook-events ...` command was then asked to run `git status --short` through Bash. The run stopped after the first tool use because `--max-budget-usd 0.05` was exceeded, but the hook event itself completed first and proved transparent rewrite:

- Claude emitted `SessionStart` and `UserPromptSubmit` hook responses with exit code 0.
- Claude emitted `PreToolUse:Bash`.
- The `PreToolUse` hook response returned `hookSpecificOutput.updatedInput.command`.
- The updated command invoked `Packet28 hook reducer-runner`.
- The rewrite carried `--family git`, `--kind git_status`, and the original `git status --short` command.

Representative captured line from `/tmp/packet28-claude-live.out`:

```text
hook_event=PreToolUse outcome=success updatedInput.command="... Packet28 hook reducer-runner --root <temp-root> --family git --kind git_status ... -- git status --short"
```

The bounded model run reported `error_max_budget_usd` after the hook response, so this artifact proves hook invocation/rewrite but not completion of the underlying Bash command.

## Gemini CLI

Result: pass for generated hook config and Packet28 doctor verification.

Setup used isolated `HOME`/`XDG_CONFIG_HOME` directories:

```sh
HOME=<temp-home> XDG_CONFIG_HOME=<temp-home>/.config target/debug/Packet28 setup --runtime gemini --root <temp-root> --yes
HOME=<temp-home> XDG_CONFIG_HOME=<temp-home>/.config target/debug/Packet28 doctor --agent gemini --root <temp-root> --json
```

Doctor returned `ok=true`, required `gemini_hook_config=true`, and required `runtime_rewrite_support=true`. The verified config path was `<temp-home>/.gemini/settings.json`, with a `hooks.BeforeTool` entry matching `run_shell_command` and a command containing `hook gemini`.

The actual Gemini CLI was also invoked against the isolated temp home. It read `<temp-home>/.gemini/settings.json` and stopped before a model run because the temp settings did not contain auth. That confirms the installed CLI reads the generated settings file, while Packet28 doctor verifies the hook shape.

## OpenCode

Result: pass for installed OpenCode loading the generated plugin config.

Setup used isolated `HOME`/`XDG_CONFIG_HOME` directories:

```sh
HOME=<temp-home> XDG_CONFIG_HOME=<temp-home>/.config target/debug/Packet28 setup --runtime opencode --root <temp-root> --yes
(cd <temp-root> && HOME=<temp-home> XDG_CONFIG_HOME=<temp-home>/.config opencode debug config --log-level ERROR)
```

`opencode debug config` reported the generated plugin as a loaded global plugin:

```json
{
  "plugin": ["file://<temp-home>/.config/opencode/plugins/packet28.ts"],
  "plugin_origins": [
    {
      "spec": "file://<temp-home>/.config/opencode/plugins/packet28.ts",
      "scope": "global"
    }
  ]
}
```

`Packet28 doctor --agent opencode --root <temp-root> --json` also returned `ok=true` with required `opencode_plugin=true` and required `runtime_rewrite_support=true`.

## Cleanup

Temporary Packet28 daemons started by these setup runs were stopped with `Packet28 daemon stop --root <temp-root>` after the smoke checks.
