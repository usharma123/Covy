# Packet28 Agentic Context Ideas

This note tracks high-leverage ideas that go beyond RTK/ICM parity and are specific to making coding agents spend less context while making better next-step decisions.

## Priority Ideas

| Idea | Agent benefit | First implementation slice | Evidence gate |
|---|---|---|---|
| Plan-to-test map validation | Prevents agents from claiming weak verification after edits. | Broker `validate_plan` now returns `test_gate_score` based on missing mapped gates, broad-suite fallback, missing mappings, and stale cached testmaps; MCP exposes the same response through `packet28.validate_plan`, and `Packet28 plan validate` makes it reproducible from the CLI. | Evidence: mapped, broad, missing-mapping, stale-testmap, CLI parsing, MCP tool-list tests, plus `plan-validation-cli-20260515` real-repo artifact. |
| Context ROI ledger | Lets agents prefer commands and memories that historically saved the most tokens for the current repo. | `Packet28 gain --json` now exposes route-level ROI from recorded compact/raw token deltas, and the dashboard surfaces top saved routes across JSON, text, HTML, and TUI output. | Evidence: `test_run_reduces_git_status`; `test_dashboard_shows_local_product_metrics`; future slices should persist downstream follow-up counts. |
| Evidence freshness scoring | Stops stale reads/searches from anchoring current decisions after edits. | Broker edit/inspect context now emits an `evidence_freshness` section with a compact freshness score for changed paths and symbols, and plan validation warns when edit steps touch changed-since-checkpoint paths without refreshed read evidence. | Evidence: `broker_edit_context_surfaces_evidence_freshness_for_changed_paths`; `validate_plan_warns_when_edit_relies_on_stale_evidence_after_checkpoint`; future slices should downrank cached snippets directly. |
| Hypothesis checkpoints | Helps agents carry explicit assumptions across handoff without replaying long transcripts. | `Packet28 hypothesis add/confirm/reject/list` and MCP `packet28.hypothesis_add/list/resolve` record active assumptions as broker decision events with `hypothesis:` IDs, including optional related paths, symbols, and artifact IDs that render in broker context and list output. | Evidence: `test_hypothesis_cli_tracks_active_assumptions`; `test_packet28_mcp_hypothesis_tools_track_active_assumptions`; `active_decisions_render_related_paths_and_symbols`; `agenty_state_snapshot_derives_current_task_state`. |
| Failure fingerprint memory | Turns repeated build/test failures into reusable local advice. | Failed `Packet28 run` records now include a deterministic `failure_fingerprint`, and `Packet28 gain --failures` surfaces that key with repeat counts plus the next successful same-directory command and changed paths as fix evidence. | Evidence: `test_gain_reports_failed_and_fallback_runs`; future slices should promote repeated fingerprints into explicit advice. |
| Scoped wake-up packs | Reduces startup context by matching memory to the requested path/symbol/task type instead of broad project recall. | `Packet28 wakeup` and MCP wakeup now accept path, symbol, and intent filters; scoped JSON and rendered packs prune irrelevant candidates. | Evidence: `test_wakeup_scopes_context_by_path_symbol_and_intent`; broader `cargo test -p suite-cli wakeup` also preserves SessionStart wake-up injection. |
| Agent action critic | Catches risky next actions before execution, not after output reduction. | Broker `choose_tool` and `edit` contexts now emit an `action_critic` section for missing tool intent, destructive command shapes, broad unscoped searches, missing edit scope, and read-before-edit gaps on focused paths. | Evidence: `choose_tool_action_critic_flags_missing_intent_and_risky_commands`; `edit_action_critic_flags_missing_scope_and_unread_paths`; future slices should add hook/MCP surfacing. |
| Experiment manifest verifier | Prevents maturity claims from drifting away from actual artifacts. | `Packet28 verify experiments --manifest <json>` validates JSON experiment manifests for non-empty IDs, required workflows, command evidence, existing artifact paths, duplicate IDs, metric thresholds, runtime versions, and unexpected fallback reasons; the repo now has a default `docs/experiments/manifest.json` covering runtime-live, real-repo, and fff search-backend evidence. | Evidence: `test_verify_experiments_checks_manifest_evidence`; `Packet28 verify experiments --root . --json`; future slices should wire this into CI. |

## Research Rules

- Prefer local deterministic signals before LLM calls: coverage, test maps, git status, reducer stats, memory FTS/vector scores, and task state.
- Every new context idea needs a compact-output metric and a correctness metric.
- A feature is not mature until it is exercised through at least one real agent workflow and one deterministic test.
- Warnings should guide agents toward cheaper or safer actions without blocking unless Packet28 has strong local proof.
- Avoid adding schema fields unless the same value is used by CLI, MCP, dashboard, or handoff paths.
