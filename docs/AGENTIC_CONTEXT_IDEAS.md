# Packet28 Agentic Context Ideas

This note tracks high-leverage ideas that go beyond RTK/ICM parity and are specific to making coding agents spend less context while making better next-step decisions.

## Priority Ideas

| Idea | Agent benefit | First implementation slice | Evidence gate |
|---|---|---|---|
| Plan-to-test map validation | Prevents agents from claiming weak verification after edits. | Broker `validate_plan` now returns `test_gate_score` based on missing mapped gates, broad-suite fallback, missing mappings, and stale cached testmaps; MCP exposes the same response through `packet28.validate_plan`, and `Packet28 plan validate` makes it reproducible from the CLI. | Evidence: mapped, broad, missing-mapping, stale-testmap, CLI parsing, MCP tool-list tests, plus `plan-validation-cli-20260515` real-repo artifact. |
| Context ROI ledger | Lets agents prefer commands and memories that historically saved the most tokens for the current repo. | `Packet28 gain --json` now exposes route-level ROI from recorded compact/raw token deltas plus downstream follow-up counts from same-directory run-savings timelines, and the dashboard surfaces top saved routes across JSON, text, HTML, and TUI output. | Evidence: `test_run_reduces_git_status`; `test_dashboard_shows_local_product_metrics`; `gain --json` route ROI includes `downstream_followup_count` and `avg_followups_per_invocation`. |
| Evidence freshness scoring | Stops stale reads/searches from anchoring current decisions after edits. | Broker edit/inspect context emits an `evidence_freshness` score, plan validation warns on stale changed-path edits, relevant context marks/downranks cached snippets that mention changed paths without refreshed reads, and reducer search ranking prefers freshly read changed paths over stale changed paths when other signals are comparable. | Evidence: `broker_edit_context_surfaces_evidence_freshness_for_changed_paths`; `validate_plan_warns_when_edit_relies_on_stale_evidence_after_checkpoint`; `relevant_context_marks_and_downranks_stale_changed_path_context`; `search_ranking_prefers_fresh_changed_path_over_stale_changed_path`. |
| Hypothesis checkpoints | Helps agents carry explicit assumptions across handoff without replaying long transcripts. | `Packet28 hypothesis add/confirm/reject/list` and MCP `packet28.hypothesis_add/list/resolve` record active assumptions as broker decision events with `hypothesis:` IDs, including optional related paths, symbols, and artifact IDs that render in broker context and list output. | Evidence: `test_hypothesis_cli_tracks_active_assumptions`; `test_packet28_mcp_hypothesis_tools_track_active_assumptions`; `active_decisions_render_related_paths_and_symbols`; `agenty_state_snapshot_derives_current_task_state`. |
| Failure fingerprint memory | Turns repeated build/test failures into reusable local advice. | Failed `Packet28 run` records now include a deterministic `failure_fingerprint`; `Packet28 gain --failures` surfaces fix advice; `Packet28 gain --failures --remember-advice` persists confirmed repeated-failure fixes as local feedback memory; broker context renders recent `failure_advice` from the same run-savings ledger. | Evidence: `test_gain_reports_failed_and_fallback_runs`; `broker_context_surfaces_failure_advice_from_run_savings`; feedback search can recall remembered `failure-advice`. |
| Scoped wake-up packs | Reduces startup context by matching memory to the requested path/symbol/task type instead of broad project recall. | `Packet28 wakeup` and MCP wakeup now accept path, symbol, and intent filters; scoped JSON and rendered packs prune irrelevant candidates. | Evidence: `test_wakeup_scopes_context_by_path_symbol_and_intent`; broader `cargo test -p suite-cli wakeup` also preserves SessionStart wake-up injection. |
| Agent action critic | Catches risky next actions before execution, not after output reduction. | Broker `choose_tool` and `edit` contexts now emit an `action_critic` section for missing tool intent, destructive command shapes, broad unscoped searches, missing edit scope, and read-before-edit gaps on focused paths; MCP exposes `packet28.action_critic` for focused pre-action checks; Claude PreToolUse hooks surface critic guidance as a non-blocking allow reason. | Evidence: `choose_tool_action_critic_flags_missing_intent_and_risky_commands`; `edit_action_critic_flags_missing_scope_and_unread_paths`; MCP tool-list exposure; `pretool_hook_output_surfaces_action_critic_without_rewrite`; `pretool_hook_output_preserves_rewrite_with_action_critic`. |
| Experiment manifest verifier | Prevents maturity claims from drifting away from actual artifacts. | `Packet28 verify experiments --manifest <json>` validates JSON experiment manifests for non-empty IDs, required workflows, command evidence, existing artifact paths, duplicate IDs, metric thresholds, per-metric artifact evidence strings, artifact-backed allowed fallback reasons, runtime versions, and unexpected fallback reasons; the repo now has a default `docs/experiments/manifest.json` covering runtime-live, fixture-suite, real-repo, fff search-backend, plan-validation, Claude Code navigation, and release-smoke evidence, with `.github/workflows/experiment-manifest.yml` enforcing the verifier on manifest, experiment, and suite CLI changes. | Evidence: `test_verify_experiments_checks_manifest_evidence`; `Packet28 verify experiments --root . --json`; CI workflow `Experiment Manifest`. |
| Search backend fallback provenance | Makes optional backend experiments observable instead of silently falling back. | `p28` records `fff auto preferred backend failed: ...` in search engine fallback provenance when `P28_FFF_AUTO=prefer` is requested but `fff-mcp` cannot launch, while still returning Packet28 native indexed or legacy results. | Evidence: `p28_auto_prefer_records_fff_backend_failure_before_native_fallback`. |
| Verification intent critic | Catches premature finalization before commit/push/merge-style actions. | Action critic now emits `verification_gap` when choose-tool context asks to commit, push, finish, or finalize without recent test/build/diff evidence in the task snapshot. | Evidence: `choose_tool_action_critic_flags_finalization_without_recent_verification`. |
| Context budget preflight | Prevents agents from asking for broad context under tiny budgets and then acting on incomplete evidence. | Broker context now emits a `budget_preflight` warning in `budget_notes` when an explicit low `budget_tokens` request includes broad search/read sections without focus paths or symbols; budget-pruning notes merge into the same section when both warnings apply. | Evidence: `budget_preflight_warns_on_low_budget_broad_context_without_focus`; warning disappears with focused paths or default budget. |
| Experiment replay scorer | Turns experiment artifacts into a repeatable scorecard instead of static summaries. | `Packet28 verify experiments --score` now emits compact per-workflow reproducibility, artifact backing, fallback clarity, and freshness scores alongside manifest issues. | Evidence: `verify_experiments_score_passes_backed_artifact_under_compact_budget`; `verify_experiments_score_fails_missing_evidence_below_threshold`. |
| Agent route recommender | Uses ROI, failure advice, and freshness to suggest the next Packet28 command directly. | MCP `packet28.recommend_next_tool` now returns compact command recommendations using local run-savings ROI, repeated-failure success advice, and focused changed-path freshness. | Evidence: `recommend_next_tool_changes_with_focus_freshness_and_roi`; recommendation payload token estimate stays below 256 in the focused fixture. |
| Handoff contradiction detector | Flags handoff packets that contain unresolved assumptions contradicted by later tool evidence. | `prepare_handoff` responses now include warning strings when active `hypothesis:*` decisions appear contradicted, rejected, refuted, or falsified by recent tool evidence mentioning the hypothesis, related paths, or related symbols. | Evidence: `prepare_handoff_warns_when_tool_evidence_contradicts_active_hypothesis`; contradiction count is exposed as `warnings.len()`. |
| Handoff readiness scorer | Helps agents decide whether to hand off now or keep working locally. | `prepare_handoff` responses now include a compact readiness object with score, status, and reasons derived from handoff readiness, checkpoint presence, open questions, contradiction warnings, next-action clarity, and recent verification evidence. | Evidence: `prepare_handoff_readiness_score_rises_after_verification_evidence`; readiness JSON stays under 512 bytes in the fixture. |
| Tool outcome validator | Catches cases where an agent interprets a failed or fallback tool result as success. | MCP `packet28.validate_tool_outcome` classifies the latest matching run-savings outcome as success, fallback, missing artifact, stale artifact, or failure with a short next action. | Evidence: `validate_tool_outcome_does_not_treat_fallback_as_success`; fallback provenance is not classified as success. |
| Context debt ledger | Shows which stale reads, unresolved questions, and unverified edits are accumulating across a task. | Broker context now emits `context_debt` with counts for stale paths, open questions, unverified edits, and contradicted hypotheses plus payoff commands to clear each debt type. | Evidence: `broker_context_debt_clears_after_reads_questions_and_verification`; debt payload stays under 1KB and clears after read/test/question resolution. |

| Patch risk preflight | Warns before edits when touched paths have high fanout, missing test maps, or stale context debt. | MCP `packet28.patch_risk` scores pre-edit path risk from shared-path heuristics, cached testmap mappings, missing mappings, and recent failure/fallback records, returning required checks. | Evidence: `patch_risk_requires_broader_checks_for_shared_unmapped_paths`; shared unmapped path requires broader checks than mapped leaf path. |
| Handoff replay verifier | Tests whether a prepared handoff is sufficient for a fresh worker to choose the same next action. | MCP `packet28.verify_handoff` reads a stored context artifact and checks for objective, next-action, debt, and evidence handles before replay. | Evidence: `verify_handoff_fails_when_next_action_is_missing`; verifier summary stays under 512 bytes in the missing-next-action fixture. |
| Prompt pressure simulator | Shows when a handoff packet will crowd out the actual next task prompt. | MCP `packet28.prompt_pressure` estimates stored handoff context plus next-prompt tokens against a target budget and reports the largest removable sections. | Evidence: `prompt_pressure_identifies_largest_removable_section`; response stays under 768 bytes while identifying the oversized section. |

| Handoff compression advisor | Suggests the cheapest removals to make an over-budget handoff replay-ready. | MCP `packet28.handoff_compress` recommends dropping non-critical sections while protecting objective, next-action, debt, and evidence-freshness anchors. | Evidence: `handoff_compress_preserves_objective_and_next_action_sections`; response stays under 1KB and does not recommend protected anchors. |

## Research Rules

- Prefer local deterministic signals before LLM calls: coverage, test maps, git status, reducer stats, memory FTS/vector scores, and task state.
- Every new context idea needs a compact-output metric and a correctness metric.
- A feature is not mature until it is exercised through at least one real agent workflow and one deterministic test.
- Warnings should guide agents toward cheaper or safer actions without blocking unless Packet28 has strong local proof.
- Avoid adding schema fields unless the same value is used by CLI, MCP, dashboard, or handoff paths.
