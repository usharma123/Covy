# Packet28 v0.2.66

This hotfix prevents Packet28 from multiplying background processes during multi-agent sessions.

- Concurrent clients serialize daemon startup and reuse pooled connections.
- Finishing a Claude subagent never requests an automatic agent relaunch.
- Daemon-managed relaunch is opt-in. Old setup-generated `claude --continue` and `packet28-agent` relaunch commands are blocked, even before setup is rerun.
- Background daemons and HTTP hook servers detach from their spawning hook session. Exited children are reaped.
- `packet28 uninstall --root /path/to/workspace` disables hooks, stops that workspace's daemon and HTTP server, and removes its local hook and MCP entries. Unrelated hooks and workspace data are preserved. Shared global integrations are reported for manual review.
- Releases publish all five npm packages through GitHub OIDC trusted publishing.
- Setup reports indexing as deferred when Git has uncommitted changes, including newly installed configuration. It no longer reports the installation as failed for that condition. Commit or stash those files and rebuild the index when ready.

The v0.2.65 release stopped before publication because its Linux shared-library build used the static musl target. This release builds the preload library separately for GNU libc, retains static musl CLI binaries, and synchronizes the child-exit test fixture before it exits.

## Upgrade and restart

Close existing agent sessions, then upgrade in each configured workspace:

```sh
npm install -g packet28@0.2.66
cd /path/to/workspace
packet28 daemon stop
```

Wait for the old daemon to exit. Stop any old HTTP server process that remains, using its verified PID. Updating the npm package does not replace either running process, and the older HTTP server has no authenticated shutdown endpoint. Then reinstall the workspace hooks and restart your agent sessions:

```sh
packet28 setup
```

## Remove Packet28 from a workspace

```sh
packet28 uninstall --root /path/to/workspace
npm uninstall -g packet28
```

Run workspace uninstall for each configured workspace before removing the npm package. npm uninstall alone does not stop running processes or remove agent configuration. Review any warnings and shared integration paths printed by workspace uninstall. Processes already launched by an older version may still need to be stopped manually.
