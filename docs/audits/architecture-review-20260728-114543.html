Confirmed problem

Real shim requests omit a task ID, so the daemon loads the active task. Task labels and mutable snapshot focus terms then affect section selection, excerpts, the focus line, and the rendered header. Identical source can therefore produce different bytes.

Solution

Make stable rewriting a pure function of source, path, schema, budget, and stable repo configuration. Keep focus paths, decisions, questions, and next actions in the already replaceable Packet28 brief.

Wins

  • stable interface bytes
  • adaptive state stays local
  • cache identity narrows
  • brief gains leverage
Evidence boundary: byte instability is verified; provider-level cache placement, token cost, and net savings are not. Keep passthrough as the baseline and gate a stable mode on the controlled measurements in the addendum.

What is already strong

  • Acyclic dependency graph. Most edges point toward packet and foundation contracts.
  • Deep scheduler. One typed interface hides DAG validation, mutation, ordering, and budget enforcement.
  • Broad behavioral coverage. 1,099 test functions across 26 of 28 crates; full locked suite passed before a concurrent local edit.
  • Idiomatic borrowing. No production &String or &Vec<T> parameters found; strings, slices, and paths are used well.
  • Deliberate dynamic dispatch. The main owned trait object and reducer callbacks sit at real runtime-selection seams.
  • Deterministic contracts. Packet hashing, schema registry, route catalog, scheduler failures, and index parity receive focused tests.
  • Unsafe stays peripheral. It is concentrated in FFI, mmap, signals, and syscalls rather than core algorithms.
  • Useful local gate. Formatting, strict Clippy, and targeted/full tests are already scripted.

Rust-practice debt

  • Unsafe contracts: 17 focused undocumented_unsafe_blocks warnings; Linux public unsafe hooks lack Safety docs.
  • Cloning: roughly 60 focused redundant_clone warnings; the largest verified case clones the whole context section vector before pruning.
  • Allocations: line counting and coverage reporting collect intermediate vectors; daemon merge helpers allocate nested sets/vectors.
  • Large Copy values: 48–88 byte query/budget structs are repeatedly passed by value.
  • State modeling: task lifecycle uses parallel booleans; search status is a String plus optional fields. Runtime enums fit better than PhantomData typestate.
  • Public errors: reusable search, daemon, diff, and test libraries leak anyhow; typed sources disappear into strings.
  • Corruption handling: a partial search-index record is accepted as clean EOF.
  • Backpressure: unbounded subscriber queues and thread-per-connection servers have no read deadlines.

Where Tokio earns its cost

There is no production Tokio dependency today; the only matches are fixture text.

  • MCP proxy: async stdio, request-ID routing, per-upstream timeouts, concurrent requests, and owned child cleanup instead of one serial loop.
  • packet28d transport: structured connection tasks, bounded subscriber channels, socket deadlines, cancellation, and TCP/Unix shutdown under one lifecycle.
  • Wait/watch/notifications: replace sleep/poll loops and the single synchronous debounce processor with timers, signals, and bounded task ownership.

suite-cli/src/cmd_mcp_proxy.rs:40–86 · packet28d/src/main.rs:225–247 · server.rs:90–106 · watch.rs:370–404 · launch.rs:3–60 · suite-cli/src/cmd_mcp.rs:269–300

Where Tokio does not help by itself

  • Parsing, repository scans, bitmap work, index construction, SQLite, serialization, and filesystem writes remain blocking or CPU-heavy.
  • Keep Rayon for data parallelism; use bounded blocking workers or spawn_blocking at an async boundary.
  • Do not place synchronous SQLite or full-snapshot writes inside async tasks and call the architecture “non-blocking.”
  • First remove global lock-held I/O and write amplification; an async runtime cannot repair those ownership defects.

Controlled prompt-cache experiment

Test byte stability before promising savings

  1. 1 · passthrough: untouched instruction content; baseline/default.
  2. 2 · stable: deterministic compression from source plus stable configuration only.
  3. 3 · adaptive: current task/snapshot-sensitive rewrite; experimental comparator.

Exercise cold start, second request, compaction, active-task A→B, snapshot drift, and fresh-worker handoff. Require identical stable-prefix hashes across task/snapshot changes.

Record per request

churn_rate = creation / (creation + read)
reuse_multiple = read / max(creation, 1)
effective_cost = creation_cost + read_cost
compaction_rewarm_tokens

Success criterion: stable hashes plus lower effective cache cost without harming instruction adherence. Aggregate hit rate alone is insufficient.

Claims such as “20K tokens lost,” “100% misses,” or guaranteed net savings remain hypotheses until provider prompt ordering and cache boundaries are measured.

Performance-first sequence

Persistence owner and lock split → incremental index generations/segments → SQLite migrations and batch ownership → parser/test-map allocation work → Tokio for daemon and MCP orchestration.

Ground truth

What mature Rust repositories support

Cargo lockfile guidance ↗

Cargo recommends checking Cargo.lock into version control when in doubt; it captures the successful dependency graph.

Cargo workspace lint inheritance ↗

Workspace lints are supported by the claimed MSRV, but members must explicitly inherit them.

Cargo rust-version support expectations ↗

A declared minimum toolchain is a support promise and should be verified by automated tests.

Rust interface documentation guidelines ↗

Public items need examples plus Errors, Panics, and Safety contracts where relevant.

rust-analyzer negative dependency rules ↗

Its architecture guide names what lower modules must not know, making diagrams enforceable.

nextest protocol / runner / binary split ↗

Machine contracts, runner implementation, filtering, and the executable remain distinct modules.

nextest thin main ↗

The executable is eleven lines and delegates to a testable application library—matching suite-cli, not packet28d.

ripgrep error seam ↗

Reusable crates stay separate; the executable adds anyhow-style reporting and semantic exit handling.

MCP Rust SDK focused features ↗

Optional transports and child-process adapters are gated deliberately; features do not replace crate seams.

Explicit task shutdown ownership ↗

Cancellation, owned task tracking, cleanup, and bounded shutdown are explicit even if Packet28 remains synchronous.
